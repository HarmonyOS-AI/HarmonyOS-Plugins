# 一多适配质量目标

仅在用户要求质量评估、完整适配或指定质量目标时读取。局部修复可指出相关等级，但不扩大页面、设备、框架或测试范围。

这是插件自身的体验标准，借鉴 Android Adaptive App Quality 的分层思想，不是 Google 或鸿蒙官方认证。质量从低到高为 **基础可用 ready → 自适应优化 optimized → 场景增强 differentiated**；高级能力不能抵消基础缺陷。它与构建、静态检查、设备运行等验证手段独立。

| 质量要求 | 领域落点与验收 |
|---|---|
| 基础可用：CORE-01 / STATE-01 / INPUT-01 / MEDIA-01 | 沿 Flutter 约束与 OHOS 宿主链验证；窗口、折展和旋转不能重建业务身份或丢输入、滚动、媒体进度；键盘避让只由一层负责。 |
| 自适应优化：LAYOUT-01 / NAV-01 / OVERLAY-01 | 区分 LayoutBuilder 父约束与 MediaQuery 窗口信息；验证分栏、增列、路由返回、弹层及 PlatformView 在窄宽切换时同步变化。 |
| 自适应优化：ACCESS-01 | 验证字体缩放、语义、焦点和适用的外设输入；沿已有 validation 路由执行。 |
| 场景增强：FOLD-01 / DRAG-01 / STYLUS-01 | 按业务选择能力，并核实 Flutter、HADSS 与 OHOS 宿主支持；悬停需联动折痕避让。 |

保留 Flutter 原生和 HADSS 两条互斥实现路线，不因目标等级强制迁移框架。领域知识中的 PC 内容不扩大工程级质量评级范围：本版分级只覆盖手机、折叠屏、平板。

独立调用时，输出目标、适用范围、已知缺口和验证限制即可；不依赖 workflow 文件或安装目录。完整交付由调用方管理质量计划与证据；提供规则对应的具体场景与预期行为，不能仅凭代码或设计稿给整个应用评级。不适用需说明业务/硬件原因；无设备、权限不足、未执行属于未验证。
