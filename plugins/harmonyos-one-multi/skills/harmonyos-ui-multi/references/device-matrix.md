# 设备矩阵

目标设备的 **vp 尺寸与断点**基准。写高保真、判断断点覆盖、构造形态矩阵时用它。

> **数据性质**：来自华为官方硬件规格与系列设计基线
> **运行态实测值优先于本表** —— 分屏、自由窗口、
> 多任务下的实际窗口尺寸与全屏基线不同，此时以 `window.getWindowProperties().windowRect` 为准。

> **不要凭硬件分辨率推 vp**：两者不是简单换算关系，受 densityDPI 与系统策略影响。

> **查不到不等于不支持**：某项规格在官方页上没写，就记「未公开」；某行合并了多个未逐一
> 核验的 SKU，就记「需精确 SKU 核验」。**规格页缺失是信息缺口，不是否定结论** ——
> 拿"表里没有"当"设备不支持"用，是这张表最容易被误用的方式。同理，
> 某个型号不在表里只说明表没收，不说明它不存在。

## 断点阈值

| 横向断点 | 窗口宽度 (vp) | 典型形态 |
|---|---|---|
| `xs` | [0, 320) | 超小窗口 |
| `sm` | [320, 600) | 直板机竖屏、折叠外屏 |
| `md` | [600, 840) | 折叠内屏展开、小平板竖屏 |
| `lg` | [840, 1440) | 平板横屏、三折展开 |
| `xl` | [1440, +∞) | 超宽窗口 |

| 纵向断点 | 高宽比 |
|---|---|
| `sm` | < 0.8 |
| `md` | [0.8, 1.2) |
| `lg` | ≥ 1.2 |

> **阈值不可硬编码。** 官方文档明确："个别设备可根据需求通过产品化配置调整断点阈值"。
> 判定断点一律用 `UIContext.getWindowWidthBreakpoint()` 的返回值，
> 没有工具会拦 `px2vp(w) >= 600` 这类写法，只能自己盯。

## 折叠形态与窗口尺寸的关系

**同一设备的不同折叠态可能有相同的窗口尺寸。** 实测 HarmonyOS 6.0.2(22)
foldable 模拟器：

| 形态 | 窗口尺寸 |
|---|---|
| 折叠 | 1080×2504 |
| 展开 | 2224×2496 |
| **悬停** | **2224×2496（与展开相同）** |

因此**不能用窗口尺寸判断折叠态**，必须用 `display.getFoldStatus()`。
