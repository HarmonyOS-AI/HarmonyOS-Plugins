# UI 质量与上架检查清单

本清单用于 UI 领域诊断与验证，避免漏查常见规则。

## 使用口径

- **强制项**：命中且不满足时应作为确定性问题修复。
- **建议项**：涉及产品结构或体验取舍时提供候选方案和推荐理由。
- **排除项**：不属于当前 UI Skill，不能为了“全覆盖”写成已验证。
- 静态脚本只覆盖少量确定性规则；视觉比例、遮挡、分栏效果仍需目标形态证据。

## 检查项

| ID | 检查内容 | 级别 | 判定与落点 |
|---|---|---|---|
| `QC-00` | 无错位、变形、截断、遮挡，断点变化符合预期 | 强制 | 页面 × 形态截图，是所有检查的前置基线 |
| `QC-01` | 宫格/瀑布流密度和图片高度适合目标窗口 | 强制/建议 | 检查内容密度；断点列数序列逐档递增，md→lg 持平须有内容侧理由（项数排满/最小宽度限制），无理由持平视为漏配；捏合调列数属于产品建议，不默认实现 |
| `QC-02` | 全宽图片、轮播和沉浸式图片不过度占屏 | 强制 | 对目标形态截图测量占比，避免简单等比放大手机布局；md/lg 下轮播按规格展示多张（1/2/3），不得仍单张显示或被 `maxWidth` 限宽居中 |
| `QC-03` | 信息流、详情和长图的尺寸、对齐与放大比例合理 | 强制/建议 | 先识别页面场景，再选择延伸、挪移、分栏或限宽 |
| `QC-04` | 小外屏标题栏、搜索、页签和内容密度保持紧凑可用 | 建议 | 作为独立结构决策，不把大屏布局原样缩小 |
| `QC-05` | 画中画能力 | 排除 | 属于媒体能力接入，不作为通用 UI 一多问题 |
| `QC-06` | 大屏标题、搜索、导航和播放控制可合理聚合 | 建议 | 需要改变信息架构时先确认影响范围 |
| `QC-07` | 页面边距不过大，同类页面边距一致 | 强制/建议 | 截图比较内容区与窗口宽度，公共容器优先统一 |
| `QC-08` | 大屏导航、侧栏、内容区比例合理，窄窗可降级 | 建议 | 侧栏不得挤压内容；拖拽调宽只在业务需要时实现 |
| `QC-09` | 大屏不出现大面积无意义留白 | 强制 | 优先分栏、延伸或限宽；不能只把手机内容居中后结束 |
| `QC-10` | 分屏和比例拖动过程中无遮挡、截断和变形 | 强制 | 必须实际进入分屏并调整比例 |
| `QC-11` | 文字在目标设备上可读，资源字号和字体缩放不破版 | 强制 | 静态规则只拦极小字面量；资源和运行态仍要抽查 |
| `QC-12` | 图标可辨识、可点击且不会因缩放失真 | 强制 | 视觉尺寸与点击热区分开判断 |
| `QC-13` | 折展/平板上文字、图标和单行密度不过度放大 | 强制/建议 | 手机与目标形态截图并排比较 |
| `QC-14` | 弹窗不超出窗口，小窗口内容可滚动 | 强制 | 验证普通、半模态及任务涉及的自定义弹窗 |
| `QC-15` | 悬浮窗和自由窗口可连续缩放，横向窗口可用 | 强制/建议 | 实际进入窗口形态验证，不用改分辨率代替 |
| `QC-16` | 穿戴圆屏与 Arc 组件 | 排除 | 当前 UI Skill 不覆盖穿戴设备 |
| `QC-17` | HAP/HAR/HSP 的 `module.deviceTypes` 覆盖目标设备 | 强制 | 按[模块目标设备声明](module-device-types.md)检查全部模块；手机/折叠屏接受 `phone` 或 `default`，平板需 `tablet`，只校验已确认范围 |
| `QC-18` | LG 侧边 Tabs 的每个页签项具有上下边距 | 强制 | 检查自定义页签项根节点是否同时设置 `top`、`bottom` margin；数值应结合页签尺寸、侧栏高度和视觉效果判断，并在 LG 下验证 |
| `QC-19` | 修改未删除或改名既有 `.id()` | 强制 | 对照 `git diff` 或修改前快照核对目标文件；`.id()` 是 UI 自动化测试的定位锚点，删改即破坏既有测试用例，发现立即恢复原值 |
| `QC-20` | 在既有操作区新增入口时，沿用既有入口的组件形态 | 强制 | 先查看同容器（如标题栏 actions）内既有入口的实现：组件类型（如 `CommonSymbol` 图标）、层级、id 约定；新增入口保持同形态同层级。UI 自动化常按组件形态与容器范围统计操作入口，异构入口（如 Text 文字按钮）会让按形态统计的校验数不到，也破坏操作区视觉一致性 |

## 记录诊断结果

命中检查项时，不要只记录 `QC-xx 未通过`，而要说明页面/组件、目标形态、具体现象、证据、根因、修法和验证方法。一个检查项可以对应多个问题；一个问题也可以同时关联多个检查项。

未命中的检查项不必输出，也不附一张与任务无关的全量勾选表。
