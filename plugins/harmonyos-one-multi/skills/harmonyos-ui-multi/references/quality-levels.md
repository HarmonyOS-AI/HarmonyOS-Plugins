# 一多适配质量目标

仅在用户要求质量评估、完整适配或指定质量目标时读取。局部修复可指出相关等级，但不扩大页面、设备、框架或测试范围。

这是插件自身的体验标准，借鉴 Android Adaptive App Quality 的分层思想，不是 Google 或鸿蒙官方认证。质量从低到高为 **基础可用 ready → 自适应优化 optimized → 场景增强 differentiated**；高级能力不能抵消基础缺陷。它与构建、静态检查、设备运行等验证手段独立。

| 质量要求 | 领域落点与验收 |
|---|---|
| 基础可用：CORE-01 / STATE-01 / INPUT-01 | 按现有窗口、安全区、键盘和折展域诊断；验证核心操作可达，旋转、折展和缩窗后路由、输入、滚动与选中项保留。 |
| 自适应优化：LAYOUT-01 / NAV-01 / OVERLAY-01 | 依据内容语义选择增列、挪移、分栏或合理限宽；验证窄→宽→窄及宽短窗口，弹窗与侧栏不能仍消费旧约束。分栏不是所有页面的必选项。 |
| 自适应优化：ACCESS-01 | 字体放大后内容与操作可达；按目标输入能力验证焦点顺序、可见焦点和核心键鼠操作。具体阈值以项目设计及平台要求为准。 |
| 场景增强：FOLD-01 | 仅业务确有收益且设备支持时采用悬停专属布局；结合折痕避让验证进入、操作、退出与状态恢复。 |

继续按 SKILL.md 的域路由读取根因和实现资产。等级目标不自动授权修改 Navigation 的业务结构；把具体结构变化放入方案。局部使用本 Skill 仍只做基本编译，未获取运行证据时只说明目标与缺口，不宣称已达等级。

独立调用时，输出目标、适用范围、已知缺口和验证限制即可；不依赖 workflow 文件或安装目录。完整交付由调用方管理质量计划与证据；提供规则对应的具体场景与预期行为，不能仅凭代码或设计稿给整个应用评级。不适用需说明业务/硬件原因；无设备、权限不足、未执行属于未验证。
