# 高保真流程契约

本文件只定义全流程中高保真如何与批次 SPEC 协作。设备外观、布局、HarmonyOS 设计基线和 HTML 自检规则来自 UI 领域 Skill 的高保真知识。

## 输入与边界

- 每批生成前读取 `$OM/decisions.json` 中该批 `hifiRequired`、`issues`、任务级 `task.targetForms` 和已记录决策，不只依赖对话记忆。
- `issues[]` 是问题、方案、计划文件和验证项的唯一事实源；HTML 不得新增、删除或扩大 Issue。
- HTML 中每处目标效果引用现有 `issueId`，并与该 Issue 的目标形态和 `plannedFiles` 对齐。
- 根据 `task.targetForms` 的设备类型，按 UI 高保真规范的默认映射生成预览。包含 `phone / foldable / tablet` 时，每批的每个页面均展示四张：直板机竖屏、普通双折叠展开竖屏、Pura X Max 展开横屏、平板横屏；默认不提供状态选择器或额外展开其他形态，用户明确要求时才调整。不得按本批 Issue 缩减展示；未修改的形态标注“保持不变”，不新增 Issue 或扩大施工、测试范围。
- HTML 只是施工的视觉依据，不关联 `verificationPlan`、验证结果或 evidence。

## 生成与确认

- 每批只生成 `$OM/output/html/hifi-<batchId>.html`；批内多页时在同一文件中按页面分节。
- 用户明确要求或选择高保真后，通过 `bootstrap`、`put-batch` 或 `transition-batch` 将对应批次的 `hifiRequired` 写为 `true`；要求全部批次时逐批标记，只要求个别批次时仅标记指定批次。该字段默认 `false`，只表示尚无生成要求，不代表已询问或用户拒绝。
- `hifiRequired=true` 时，直接加载 UI 领域 Skill 的高保真规范生成 HTML。只有用户明确取消才能改为 `false`；不得因修改简单、SPEC 已确认或用户同意继续而清除要求。
- 只有同时满足以下条件才属于极小改动，可以不提示高保真：仅涉及单页的单个局部组件；只调整一个直观属性或约束；不改变导航、分栏、模块排列、断点分支、折展状态或交互结构；不同目标形态没有不同视觉方案。单个间距、尺寸、圆角、颜色、文字截断或固定避让值修正可归入此类。
- 尚未要求高保真、也未明确拒绝时，其他改动在展示 SPEC 时通过一次交互提供三个选择：“先生成高保真预览，再确认施工”“确认 SPEC，直接施工”“调整 SPEC”。询问范围与本次展示的批次一致；涉及导航、分栏、模块重排、多形态差异或交互变化时优先推荐预览。
- `batch` 模式生成当前批要求的 HTML，与本批 SPEC 一起确认；`aggregate` 模式先生成全部批次 SPEC 及所有 `hifiRequired=true` 批次各自的 HTML，再统一确认。生成任务可逐批完成，但不能只交付 B01 或用合并文件替代各批文件；未要求高保真的批次只交付 SPEC。
- 交付确认前，按账本逐批核对要求的 HTML 是否存在、实际页面与设备形态是否齐全，并完成 UI 领域规范的 HTML 自检和预览。缺失时补齐或说明失败，不得仅凭字段或文件名宣称完成；不得以施工后补生成代替施工前确认。
- 用户修改视觉方案时，先更新对应 Issue，再同步刷新 HTML；施工只使用最后一次确认的 SPEC 与 HTML。

## 施工关联

SPEC 控制文件范围和方案边界，HTML 控制布局、比例、位置、间距和组件状态。视觉或交互结构改变时更新原 HTML；仅代码细节、测试状态或报告变化时不更新。
