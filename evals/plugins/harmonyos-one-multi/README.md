# 一多插件评测

日常回归完全离线，不调用模型：

```bash
npm run evals
npm run plugins:validate
npm run evals:one-multi:history
```

`migration-inventory.json` 保留 230 个迁移文件的原始映射与哈希。历史审计只读取冻结提交 `c7213b1b43d1d060f5e428d7278f1ba3db38ee3e`；日常检查验证当前资源存在、链接可解析、插件独立加载与打包、扫描和授权行为以及证据/报告契约，允许当前源码继续维护。

五个 Skill 均有独立入口：`skills/<skill>/run.mjs`。H5 入口实际运行扫描器；Flutter 入口检查独立资源与两种路线的示例。文档结构检查不再宣称能证明 Agent 路由、决策或交付行为正确。

## 真实 Agent 前后对比

前提：本机有 OpenCode **1.18.29**，并已配置 **bailian-blue/qwen3.8-max**。评测读取既有提供商配置，不将密钥写入交付报告。命令会调用模型，需要正常的提供商配额与较长执行时间。

```bash
# 开发集：14 个场景，每版两次；用失败证据迭代。
npm run evals:one-multi:compare -- --output .eval-runs/one-multi/p1-final --split development
# 最终检查：同目录复用相同源码/评测器/配置的开发结果，补齐 6 个保留场景。
npm run evals:one-multi:compare -- --output .eval-runs/one-multi/p1-final
```

也可只运行一个开发场景：`--split development --case workflow-continuous`。改变源码、依赖、提供商配置或评测器后必须使用新目录；不要覆盖先前失败样本。`STOP_AFTER_PAIR` 文件可让正在运行的比较在完成当前配对与评分后停止。

- `behavior/frozen.json` 固定输入工程构造器、20 个任务提示及评分规则的 SHA-256。
- 每版每场景两次，完整一次比较是 **80 次执行 + 40 次匿名配对评分**。同一场景的两版同时运行，每次交替启动顺序，最多两个任务执行并发。
- 每个任务使用独立的 OpenCode 服务、配置和项目目录。插件安装在项目外的独立目录，避免扫描器把插件示例当成工程源码；只开放这个插件目录，其他外部目录继续拒绝。只加载对应版本的真实 OpenCode 插件，不向被测 Agent 提供评分规则、其他版本或历史结果。
- Bash 工具在执行前注入测试桩路径，避免 shell 启动脚本覆盖继承的 PATH。构建/设备命令明确标注合成环境；无 SDK、模拟器或真机验证。
- 文件差异、资源读取、账本与报告采用程序断言；真实诊断和方案采用匿名裁判，引用轨迹 `T<n>` 或具体产物。标题、关键词和用例 ID 本身不是行为通过依据。
- 任务超时、工具/提供商故障、评分失败保留在结果中，不从分母删除。不同协议的排障试跑单独保留，不能用于宣称正式成功率。

## 产物与验收

输出目录中保存 `comparison.html`、`comparison.json`、`configuration.json`、`deterministic.json`、冻结协议、两个源码副本以及每次任务/裁判的原始 JSON。运行中另有 `progress-*.json`，包含最近一次持久化的部分轨迹；正常结束后由完整记录替代。

同目录会验证版本与配置并复用已完成的原始记录；如需重新调用模型复现，请指定一个新的 `--output` 目录。匿名裁判通过带完整条目约束的 `submit_grade` 工具提交结果，缺少标准、证据或有效评分均不得通过。

只有完整样本、确定性回归通过、新版成功率至少 90% 且不低于旧版、Workflow 目标成功率至少提升 10 个百分点或已授权场景冗余确认减少至少 50%、严重错误为零且其他领域成功率不下降，报告才标记质量提升。报告列出两次运行一致性、退化项和评分失败。20 个合成场景的结果不能外推为全面质量保证。

基线上的新能力断言可能因缺少相应接口失败；这与已有行为回归分开阅读。`deterministic.json` 保留完整断言输出和失效链接清单，既展示缺陷的失败转通过，也保留旧功能契约的独立验证入口。
